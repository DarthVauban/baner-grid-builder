# Кампанії звичайних форм

## Архітектурне рішення

Передзамовлення залишається частиною домену заявок і звичайних форм. Воно не є типом pop-up банера: банери мають інший редактор, аналітику та життєвий цикл, тоді як тут головним результатом є валідована заявка в розділі «Заявки».

Для розміщення форми на вітрині використовується окрема сутність `application_form_campaigns`. Вона пов’язує опубліковану звичайну форму з поточним поколінням каталогу Хорошоп, оформленням кнопки, окремими desktop/mobile селекторами та цільовими товарами.

Покрокові форми з логікою не підтримують кампанії розміщення і залишаються без змін.

## Таргетинг

- Ціль на товар без модифікації охоплює всі його модифікації.
- Ціль на модифікацію працює лише для цієї модифікації/SKU.
- Якщо вибрати весь товар, окремі цілі його модифікацій автоматично прибираються як зайві.
- Кампанію не можна активувати для неопублікованої форми, застарілого покоління каталогу або неактивної/прихованої цілі.
- Режим «лише коли немає в наявності» перевіряє серверний снапшот каталогу, а не значення з браузера.

## Встановлення на сайт

У магазин вставляється один глобальний скрипт, який можна скопіювати у вкладці «Розміщення на сайті». Додавати окремий код для кожної форми або товару не потрібно. На кожній сторінці скрипт визначає товар, запитує активну кампанію і вставляє кнопку лише за наявності точної цілі.

Desktop і mobile мають незалежні CSS-селектори та позиції вставки. Mobile-контракт застосовується лише за одночасної наявності мобільного User-Agent і viewport не ширше 760 px.

## Цілісність заявки

Публічний resolver повертає короткоживучий підписаний контекст кампанії. Під час надсилання сервер повторно перевіряє:

- активність кампанії, форму, розклад і покоління каталогу;
- відповідність товару або модифікації збереженій цілі;
- домен сторінки підключеному магазину;
- актуальну наявність для відповідного режиму.

Назва, SKU, ціна, зображення та зовнішні ідентифікатори товару беруться з каталогу Хорошоп. Дані товару, передані браузером, не можуть підмінити цей снапшот. Заявка зберігає ідентифікатор і назву кампанії та має джерело `preorder_campaign`.

## Перехід зі старого редактора

Міграція деактивує старі глобальні кнопки оплати частинами, не видаляючи їхні записи. Старі API залишені для сумісності й історії, але у звичайному інтерфейсі конструктора їх замінює редактор кампаній розміщення.

Нові звичайні форми створюються без наперед заданих полів. Кожне поле, його тип, активність, обов’язковість і показ в основній інформації заявки задаються в редакторі. Старі системні поля стають звичайними кастомними полями після наступного збереження форми.
