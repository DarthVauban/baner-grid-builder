# Керування популярністю товарів Хорошопа

Інструмент доступний за `/tools/horoshop-popularity` користувачам з доступом `horoshop_popularity`. Він використовує синхронізований зовнішній каталог Хорошопа в `search_horoshop_*`. Локальний каталог `used_smartphone_*` не використовується.

## Вибірка

- Товари показано на рівні батьківського товару. Фільтри: пошук за назвою або артикулом, категорія, кілька брендів, наявність, нульова або додатна популярність, а також діапазон від 0 до найбільшої популярності в каталозі. У списках категорій і брендів є пошук за текстом.
- У поле пошуку можна вставити список назв чи артикулів, по одному значенню на рядок. Точний артикул батьківського товару або модифікації має пріоритет над назвою. Однакові збіги зводяться до одного батьківського товару. Невідомі й неоднозначні значення показуються окремо.
- Після створення вибірки зі списку таблиця показує лише знайдені товари; інші фільтри звужують цю вибірку. Масова дія «Вибрати всі за фільтром» у цьому режимі охоплює лише видимі товари зі списку. Вибірку можна відредагувати або очистити.
- Масова вибірка охоплює вибрані рядки або всі товари, що відповідають поточним фільтрам. За одну операцію дозволено до 5000 батьківських товарів.

## Операція

Підтримуються встановлення значення, додавання цілого числа до поточного значення та скидання до нуля. Допустимий діапазон результату — від −1 000 000 000 до 1 000 000 000. Перед записом створюється збережений перегляд змін із вихідними й цільовими значеннями. Перегляд чинний одну годину.

Після підтвердження фоновий виконавець перевіряє актуальний експорт Хорошопа. Якщо популярність або набір модифікацій змінилися після перегляду, запис для ще не розпочатих товарів зупиняється як конфлікт. Для кожного товару надсилається однакове значення для всіх його артикулів модифікацій; для товару без модифікацій — артикул батьківського товару. Після імпорту виконавець повторно читає експорт. Лише підтверджений результат позначається успішним і оновлюється в локальній проєкції каталогу. Непідтверджені записи залишаються видимими в результаті та історії.

Операції серіалізуються з іншими записами до Хорошопа через наявний механізм `runExclusiveExternalWrite` та advisory lock `72914213`. Черга відновлюється після перезапуску сервера. Доступні стан, прогрес та історія операцій.

## API

Усі маршрути мають префікс `/api/search/horoshop/popularity` і вимагають авторизації та доступу до інструменту.

| Метод | Маршрут | Призначення |
| --- | --- | --- |
| GET | `/catalog` | Каталог, фільтри, сторінки й доступні значення фільтрів |
| POST | `/catalog/selection` | Тільки товари зі списку ID з урахуванням поточних фільтрів; повертає ID всієї відфільтрованої вибірки |
| POST | `/resolve` | Зіставлення вставлених назв та артикулів із батьківськими товарами |
| POST | `/sync` | Запуск наявної синхронізації каталогу |
| POST | `/operations/preview` | Створення перегляду змін |
| POST | `/operations/:id/apply` | Постановка переглянутої операції в чергу |
| GET | `/operations/:id` | Стан і результат операції |
| GET | `/operations` | Останні 50 завершених або запущених операцій |

Реальний запис спирається на [Horoshop API імпорту](https://horoshop.notion.site/1b6cc2897079812b9127de30b8fd106c) `products/import`, що приймає `article` та `popularity`. Правила сортування описано в [довідці Хорошопа](https://help.horoshop.ua/uk/articles/6407275-%D1%81%D0%BE%D1%80%D1%82%D1%83%D0%B2%D0%B0%D0%BD%D0%BD%D1%8F-%D0%B7%D0%B0-%D0%BF%D0%BE%D0%BF%D1%83%D0%BB%D1%8F%D1%80%D0%BD%D1%96%D1%81%D1%82%D1%8E). Після підключення реального магазину варто спершу перевірити невелику вибірку на тестових товарах: документація API не формулює окремої гарантії, що частковий імпорт лише цих двох полів збереже кожне інше поле товару.
