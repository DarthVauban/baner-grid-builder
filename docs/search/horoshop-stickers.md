# Стікери Хорошоп

Інструмент `/tools/horoshop-stickers` у блоці **Інструменти Хорошоп** масово додає та знімає ручні стікери з товарних груп. Доступ — окреме право `horoshop_stickers`; налаштування ручних стікерів доступне лише адміністратору. Вбудована політика 2FA застосовується через стандартний `requireToolAccess`.

## Початок роботи

1. Підключіть Хорошоп і дочекайтеся успішної синхронізації.
2. Довідник стікерів завантажується без повної синхронізації товарів через `icons/export`, з кешем на 5 хвилин. **Оновити** примусово перечитує його. Помилка завантаження відображається окремо й не приховує кешовані товари та бренди. Для фільтрації видно весь довідник; у списках змін непідтверджені стікери показано вимкненими. Адміністратор відкриває **Налаштувати ручні стікери**, звіряє спосіб активації кожного вибраного стікера у **Сайт → Стікери для товарів** Хорошоп та підтверджує **У властивостях товару**. Довідник `icons/export` не містить способу активації; назви та системні ID не використовуються для його вгадування. Автоматичні стікери не позначайте. Налаштування прив'язане до поточного підключення й має журнал змін.
3. Виберіть товари через фільтри, сторінку, всі результати або вставте стовпець артикулів. Артикул будь-якої модифікації вибирає всю групу; дублікати об'єднуються, неоднозначні збіги потребують ручного вибору. Артикули залишаються текстом, включно з початковими нулями.
4. Оберіть стікери для додавання та зняття. Вимкнені у Хорошоп ручні стікери можна знімати, але не додавати.
5. Натисніть **Переглянути зміни**, перевірте «було → стане», конфлікти та кількість змін. Лише **Застосувати** ставить операцію у серверну чергу.

Вибір усіх результатів повертає фіксований набір ID; зміна фільтра не розширює його. Можна виключати окремі групи та зберігати іменовані вибірки. Максимум — 20 000 груп за операцію. Збережені вибірки перевіряються повторно перед підготовкою змін.

Бренди підтримують рядки, об'єкти з назвою та локалізовані назви Хорошоп. Для раніше синхронізованих товарів із порожньою колонкою бренду інструмент читає наявні поля бренду зі збереженого експорту товару або його модифікацій; повна повторна синхронізація для цього не потрібна.

## Виконання й історія

Дані операцій, знімки стікерів, склад модифікацій, результати та автори зберігаються в PostgreSQL. Worker у `src/server.js` працює незалежно від HTTP-запиту; URL із `?operation=<uuid>` відновлює вікно операції після перезавантаження. Обробка пакетами до 25 товарних груп, кожен запит імпорту містить не більше 25 артикулів. **Зупинити залишок** припиняє майбутні пакети груп; поточний пакет завершує запис своїх модифікацій і проходить перевірку.

Worker використовує `runExclusiveExternalWrite` для узгодження з іншими операціями Хорошоп у процесі та PostgreSQL session advisory lock для взаємного виключення sticker workers між процесами. Після перезапуску операції зі станом `running` продовжуються: позиції `writing` спочатку звіряються з Хорошоп, тож підтверджені зміни повторно не відправляються.

**Повторити невдалі** створює новий перегляд лише для помилок і зупинених позицій. Конфлікти потребують нової вибірки та перегляду. **Повернути зміни** створює окремий перегляд зворотної операції: повертаються лише фактично змінені нею стікери, а сторонні нові стікери зберігаються. Якщо змінені стікери або склад модифікацій уже інші, повернення блокується для відповідної групи. Сам перегляд повернення нічого не публікує.

Частково записана група відновлюється тільки тоді, коли кожен набір стікерів її модифікацій точно відповідає знімку «було» або «стало» цієї операції. Сторонні зміни в будь-якій модифікації блокують таке відновлення.

CSV-звіт включає артикул, назву, стікери до/після, статус і повідомлення; значення захищені від формул Excel. Історія показує останні 50 операцій; повний результат конкретної операції доступний через її URL і звіт. Журнал `search_horoshop_sticker_events` містить створення перегляду, запуск, зупинку, завершення, підтвердження ручних стікерів і збереження вибірок.

## Контракт Хорошоп і межі

- Довідник: `icons/export`. Імпорт: `catalog/import` із **тільки** `article` та `icons` (масив назв); зняття останнього стікера передає `icons: []`.
- Імпорт явно оновлює всі актуальні експортовані артикули модифікацій групи; поле `parent_article` та інші поля товару не надсилаються. Результат повинен підтвердитися для всієї групи модифікацій.
- Перегляд отримує актуальний повний експорт каталогу. Worker повторює перевірку перед відправленням і після пакетів. Відсутнє поле `icons`/`stickers`, невідомий числовий ID, неоднакові набори стікерів модифікацій, неунікальні назви стікерів або змінений склад групи блокують небезпечний запис.
- Транспортні помилки імпорту не повторюються автоматично: остаточний результат визначає читання з Хорошоп. Невдале читання результату залишає позиції для явного повторення з попередньою звіркою.
- Хорошоп не документує умовного атомарного запису стікерів. Паралельне редагування безпосередньо в адмінці Хорошоп між перевіркою та записом не можна повністю виключити. Для великих операцій варто уникати такого одночасного редагування.
- Серверні тести перевіряють очищення останнього стікера, групову зміну, timeout після успіху, часткове застосування, відновлення, конфлікти, права, аудит, відкат і ізоляцію покоління підключення. Вони використовують імітацію API; живі товари магазину під час розробки не змінюються. Перше застосування на конкретному магазині варто виконати на невеликій вибірці та перевірити звіт.
- Інструмент змінює нативні дані Хорошоп; власного embed або DOM-селекторів вітрини немає. Desktop/mobile використовують штатне відображення стікерів платформи.

API інструмента: `/api/search/horoshop/stickers/{catalog,select,resolve,manual,selections,operations}` та `POST /api/search/horoshop/stickers/directory/refresh`. Зміни структури — append-only міграція `097_horoshop_sticker_operations.sql`; відключення магазину каскадно видаляє його локальні вибірки, операції та дозволений список.
