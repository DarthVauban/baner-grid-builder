# Спільне підключення віджетів Хорошопа

У робочому просторі відкрийте **Інструменти → Віджети для Хорошопа**. На окремій
сторінці код одразу доступний для копіювання, а нижче показані віджети, до яких
користувач має доступ. Пункт «Кнопки форм» у сайдбарі не дублюється.

Глобальні віджети вітрини встановлюються одним кодом:

```html
<script async src="https://WORKSPACE_ORIGIN/api/public/horoshop-widgets/embed.js"></script>
```

Це один код для встановлення, а не один мережевий ресурс: невеликий завантажувач
підключає скрипти активних віджетів окремо. Після публікації чи вимкнення віджета
код у шаблоні Хорошопа не змінюється. Публічний скрипт кешується до 60 секунд;
скрипти окремих віджетів мають власний час кешування.

## Глобальні підключення

| Віджет | Умова завантаження |
| --- | --- |
| Попап-банери | Підключений магазин; кампанію визначає власний `/resolve` |
| Лейбли товарів | Увімкнена опублікована версія |
| Кошик Хорошопа | Увімкнена опублікована тема |
| Меню каталогу | Увімкнена опублікована тема |
| Telegram після замовлення | Увімкнена опублікована версія |
| Кнопки форм | Є активна кампанія поточного підключення |
| Онлайн-підтримка | Є увімкнений сайт підтримки, який дозволяє origin вітрини; для порожнього списку дозволених сайтів потрібен єдиний такий сайт |
| Промооформлення товарних добірок | У URL сторінки є `mt_promo` |

Завантажувач читає поточний домен підключення Хорошопа та публічний стан кожного
віджета з PostgreSQL. На іншому домені він не запускає жодного модуля. Паролі
Хорошопа, токени та чернетки не потрапляють у браузер. Старі адреси окремих
`embed.js` залишаються доступними на час переходу. Якщо старий тег уже є на
сторінці, завантажувач не підключає той самий модуль удруге.

Мапа магазинів і скрипти, які вставляють вміст у конкретне місце сторінки,
залишаються локальними підключеннями. Зокрема, код самої товарної добірки
встановлюється на потрібній сторінці; спільний код бере на себе лише її глобальний
промозавантажувач. Для нового глобального віджета потрібно
додати його публічний маршрут і умову публікації до реєстру в
`src/modules/horoshop-widgets/widget.service.js`, а також перевірити ввімкнення,
вимкнення, повторне встановлення й обидві поверхні Хорошопа.

## Встановлення та перевірка

1. Опублікувати потрібні віджети в MT Workspace.
2. Додати спільний код перед `</body>` у глобальний шаблон Хорошопа. Якщо
   desktop і mobile мають окремі шаблони, додати той самий код в обидва.
3. Перевірити desktop і mobile окремо. Мобільна перевірка потребує мобільного
   User-Agent **і** мобільного viewport. Меню каталогу зберігає чинну межу
   `desktop-only`.
4. Після перевірки прибрати старі індивідуальні теги глобальних віджетів.

Завантажувач лише організує підключення. DOM-селектори, поведінка, публікація
та помилки кожного віджета залишаються у його модулі. Дивіться також
[DOM-контракт вітрини](horoshop-storefront-dom-contract.md).

## Товарний промобанер і онлайн-підтримка

На мобільній вітрині кнопка підтримки розташовується на 12 px вище нижнього
товарного промобанера. Висота банера вимірюється через `ResizeObserver`; зміни
контенту, ширини екрана й visual viewport автоматично оновлюють позицію.
Нижній відступ враховує `safe-area-inset-bottom`. Верхній промобанер не піднімає
кнопку чату.

Відкритий мобільний чат тимчасово приховує промобанер і вимикає його фокусування.
Після згортання чату повертається той самий банер без повторного показу чи
скидання вибраного товару. Закриття банера, завершення його таймера та зміна
сторінки зберігають свої звичайні правила; закритий банер не відновлюється.

Спільний runtime `floating-layout.js` вбудовується в обидва embed-скрипти та
працює з індивідуальними тегами й загальним завантажувачем незалежно від порядку
їх завантаження. Він керує лише власними DOM-вузлами віджетів. Desktop-позиції
не змінюються. Browser-перевірки охоплюють окремі desktop/mobile fixtures,
мобільний User-Agent і viewport, обидва порядки завантаження, зміну висоти,
відкриття/згортання чату та остаточне закриття банера.
