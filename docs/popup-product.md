# Попап із товаром

Тип кампанії `product_popup` — класичне модальне вікно з одним товаром. На desktop власне
зображення розташоване ліворуч, а контент і дії — праворуч. На mobile контент іде під зображенням;
вікно вміщується у viewport і прокручується за потреби. Preview використовує публічний embed runtime.

## Товар і ціни

Товар або конкретна модифікація вибираються з каталогу Хорошопа. Кампанія зберігає стабільні
зовнішні ID через `promoItems`; одночасно може бути вибрано рівно одну позицію. Повторний вибір
замінює попередню позицію. Номенклатура умов показу залишається окремою від рекламованого товару.

Публічний `/resolve` і admin `/preview` читають назву, поточну ціну, валюту та URL з актуальної
синхронізованої PostgreSQL-проєкції `search_horoshop_*`. Наступний показ після синхронізації отримує
оновлені дані. Snapshot ціни або URL не є джерелом для показу; прямий запит до зовнішнього
Horoshop API на кожне відкриття попапа не виконується.

`productPopup.titleOverride` змінює назву лише в банері. Порожнє значення використовує назву з
каталогу. Заголовок та текст над ним зберігаються в `content.title` і `content.eyebrow`.

Стара ціна та вигода мають незалежні перемикачі `showOldPrice` і `showSavings`:

- `oldPriceSource: catalog` читає актуальну стару ціну вибраного товару/модифікації;
- `oldPriceSource: manual` використовує `manualOldPrice` у валюті вибраного товару;
- ручна стара ціна під час збереження має перевищувати поточну;
- вигода дорівнює різниці старої та актуальної ціни, текстовий префікс задає `savingsLabel`;
- за відсутності додатної різниці стара ціна та вигода не показуються;
- налаштування не змінюють каталог, ціну кошика або ціну замовлення.

Прихований, неактивний, недоступний товар, нульова/нечислова ціна, відсутній або сторонній URL
не допускаються до публічного показу. Зміна покоління підключення ізолює кампанії попереднього магазину.

## Власне зображення

Окремі поля завантаження з кнопкою та перетягуванням використовують оформлення файлового сховища.
Для desktop рекомендований розмір **880 × 1000 px (22:25)**, для телефона — **1000 × 1000 px (1:1)**.
Мобільне зображення зберігається в `productPopup.mobileImageUrl` з фактичними `mobileImageWidth`
та `mobileImageHeight`; desktop — у `content.imageUrl`. На ширині до 640 px `<picture>` обирає
мобільний файл і показує його квадратним із кадруванням по центру. Без окремого мобільного
файлу використовується desktop-зображення, зокрема для вже створених кампаній.
Дозволено JPG, PNG та WebP до 10 МБ; інший розмір дозволений. Зображення оптимізується
спільним media storage та зберігається як WebP з фактичними шириною й висотою. Фото каталогу
не підставляється замість завантаженого зображення.

`POST /api/popup-banners/image` приймає binary image body та необов’язковий URL-encoded
`X-File-Name`. Потрібні автентифікація та доступ `popup_banners`; інші дозволи медіабібліотеки
не надаються. Повертає стандартний `{ data: MediaAsset }`. Runtime відкриває файл відносно
origin панелі, незалежно від домену магазину.

## Стилі й дії

`productPopup.elements` має окремі налаштування для eyebrow, головного заголовка, назви товару,
актуальної та старої ціни, вигоди, покупки, «Детальніше» та закриття. Для кожного доступні колір,
фон/непрозорість, шрифт, розмір (окремо для desktop/mobile) і насиченість, вирівнювання, рамка, заокруглення та відступи.
Окремо задаються фон і ширина вікна, рамка/заокруглення, затемнення, відступи контенту та проміжки.
Стилі перевіряються whitelist-схемою, довільний CSS не виконується. Мобільні відступи контенту та проміжки задаються незалежно. Зображення не має окремого
редактора стилів. Налаштування зберігаються в `product_popup` і входять до історії версій.

«Детальніше» завжди посилається на URL вибраного товару з каталогу. Покупка використовує чинний
native cart adapter: перевірені незалежні desktop/mobile order boxes, числовий native ID,
кількість і тип із нативної кнопки, підтвердження через `getProductById`. SKU не перетворюється
на native ID. Після підтвердженого додавання попап закривається; невдала спроба дозволяє повторити дію.

Публікація, пауза, умови показу, розклад та доступ успадковані від існуючих попап-кампаній.
