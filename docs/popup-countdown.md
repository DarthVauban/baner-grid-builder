# Банер із таймером

Тип кампанії `countdown` доступний у виборі промобанерів. У секції «Зворотний відлік» є два режими:

- **До заданої дати й часу** — спільний момент завершення для всіх відвідувачів. Конструктор показує часовий пояс браузера, передає дату з часовим зміщенням, а сервер зберігає її в UTC. Публічний віджет коригує поточний час за відповіддю сервера.
- **Персональний відлік** — від 1 до 43 200 хвилин (30 днів), починаючи з першого фактичного показу. Час очікування тригера не витрачає персональний таймер.

Банер показує дні, години, хвилини й секунди та автоматично приховується після завершення. Завершення не зараховується як закриття користувачем. Уже завершений таймер не з’являється після переходу або перезавантаження. Якщо фіксований термін минув під час очікування тригера, показ також скасовується.

Персональний термін зберігається в `localStorage` поточного магазину; резервні варіанти — `sessionStorage` та пам’ять сторінки. Без доступу до сховищ збереження між перезавантаженнями неможливе. Ключ залежить від публічного ID кампанії й тривалості, тому редагування тексту, дизайну або повторна публікація не перезапускають відлік. Інша тривалість або нова кампанія створюють окремий відлік. Очищення даних браузера також починає новий відлік.

Розклад, пристрої, тригери та частота показів застосовуються як для інших попапів. Початкова частота — «Кожен перегляд», щоб відвідувач бачив залишок часу на наступних сторінках. Доступні звичайні розміщення, оформлення, зображення та кнопки. Сценарій альтернатив відсутнього товару для цього типу недоступний.

Прев’ю використовує той самий віджет, але не читає й не записує персональні таймери, не надсилає аналітику та не забирає фокус із конструктора. Кожне оновлення прев’ю має власний персональний відлік.

## API та збереження

Створення, редагування й прев’ю приймають `timerConfig`:

```json
{
  "mode": "duration",
  "deadlineAt": null,
  "durationMinutes": 15
}
```

Для `mode: "deadline"` потрібен `deadlineAt` у форматі ISO 8601 із часовим зміщенням. Чернетку з минулою датою можна зберегти, але публікація поверне `422 POPUP_TIMER_EXPIRED`. Публічний resolve пропускає такі кампанії. Налаштування активної кампанії оновлюються при збереженні, як текст і дизайн звичайного попапа.

Міграція `089_popup_countdown.sql` додає `timer_config` і розширює обмеження типів. Старі кампанії отримують нейтральну конфігурацію; таймер рендериться лише для `countdown`. Конфігурація також входить до історії версій, адміністративних відповідей та публічного payload. Нові поля не змінюють шляхів API; клієнтські `create`, `update` і `preview` передають їх разом із типізованим `PopupCampaignInput`.

## Перевірки

- `tests/popup-timer.test.js`: збереження, завершення, серверний час, неактивна вкладка, ізоляція прев’ю, недоступне сховище, очищення обробників.
- `tests/popup-banners.integration.test.js`: валідація, створення, публікація, редагування, серіалізація та публічний resolve; у CI додатково виконується на PostgreSQL.
- `client/src/pages/PopupBannersPage.test.tsx`: створення персонального таймера, перемикання режиму, редагування й збереження дати.
- `tests/e2e/popup-countdown.spec.ts`: реальний Chromium окремо з desktop та mobile User-Agent і viewport; адаптивність, переходи, перезавантаження, завершення та прострочений тригер.
